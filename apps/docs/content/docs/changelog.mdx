Notable changes to Liveflux.

## 0.2.0 — Bidirectional: client → server (October 2026)

Liveflux is no longer read-only. Clients can now **send to the server**, with the same type-safety and resilience as reading:

- **`publish`** — fire-and-forget commands, with an opt-in offline outbox (queue while disconnected, flush in order on reconnect, drop-oldest + TTL) and optional idempotency keys.
- **`request` (RPC)** — correlated request/reply with typed results, per-request timeouts, cancellation via `AbortSignal`, and in-flight backpressure.
- Shipped across **every adapter** — `ws`, `sse`, `socketio`, `graphql-ws`, and `phoenix` — each proven against the shared adapter-conformance suite, so behaviour is identical on every transport.
- **`@liveflux/devtools`** now taps commands too: outbound publishes and requests appear with their status (pending → resolved / rejected) and timing.

All packages are released together at **0.2.0**. (The docs site also picked up the latest Next.js security patches.)

## 0.1.0 — Initial release (July 2026)

The first public release — a framework-agnostic realtime-state engine with swappable transports:

- **`@liveflux/core`** — connection, subscriptions, store, reconnect with backoff, and backpressure.
- **`@liveflux/react`** — the `useStream` hook, `LivefluxProvider`, and a status/error surface.
- **Adapters** — `@liveflux/ws` (generic WebSocket), `@liveflux/sse` (Server-Sent Events, reconnect + cursor resume), `@liveflux/socketio` (wraps an existing Socket.IO client), `@liveflux/graphql-ws` (graphql-transport-ws, zero-dependency), and `@liveflux/phoenix` (Phoenix Channels v2: joins, rejoin backoff, heartbeat).
- **`@liveflux/devtools`** — a dev-only panel (`npm i -D`) for inspecting any client at runtime.
- **`create-liveflux`** — an interactive scaffolder (`pnpm create liveflux@latest`).

TypeScript-first and tree-shakeable throughout; React reads go through `useSyncExternalStore` for tear-free state.
